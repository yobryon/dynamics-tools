# Parked — pending reconciliation with extracted Copilot prompts

These v1-era recipes are domain-correct (D365 F&O AOT property
semantics, AX 2012-vs-F&O deprecations, BP gotchas) but tool-surface
wrong: every recipe is framed around v1's operation-shape API
(`create_xpp_object`, `execute_object_modification`, the "17 parameters
per concreteType" pattern). v2 round-trips full AOT XML via
`xpp_create_object` / `xpp_update_object`, so the operation framing
doesn't apply.

## Why parked rather than deleted

We extracted MS-authored prompts from the GitHub Copilot D365 VS2022
extension (`Microsoft.Dynamics.Framework.Tools.GitHubCopilot.17.0.dll`)
into `misc/d365_extension_notes/prompts/`. Before rewriting these
recipes we want to:

1. Audit what's actually in those extracted prompts vs what we've
   surfaced to the agent (suspicion: we summarized and lost detail).
2. Decide the division of labor:
   - `xpp://schema/{type}` — MS XSD (machine grammar)
   - `xpp://guide/{type}` — our-voice condensed guide (LLM, in-MCP)
   - The MS prompts themselves — possibly served directly as
     additional resources, instead of being summarized
   - These recipes — durable human-facing reference, ideally
     non-overlapping with the above

After that audit we'll know what's worth keeping here vs migrating
into the MCP-served resources vs deleting outright.
